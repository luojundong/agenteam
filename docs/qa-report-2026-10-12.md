## 三、发现并修复的问题

### 问题 1：`backend-proxy-range.test.mjs` 模块加载失败（测试代码 Bug）

- **现象**：`test:conversation-sidebar` 首轮退出码 1，`backend-proxy-range.test.mjs` 在模块加载阶段报错：
  `TypeError [ERR_UNSUPPORTED_RESOLVE_REQUEST]: Failed to resolve module specifier "next/server" from "data:text/javascript;base64,..."`
- **根因（已定位并验证）**：该测试读取 `src/lib/server/backend-proxy.ts` 源码，对两处 import 做**精确字符串替换**以去掉对 `next/server` 与 `./agent-backend` 的依赖：
  - 测试期望：`import { NextResponse } from "next/server";`（带空格）
  - 测试期望：`import { agentBackendUrl } from "./agent-backend";`（带空格）
  - 实际源码（已 `Read` 确认）：`import {NextResponse} from "next/server";`（**无空格**）、`import {agentBackendUrl} from "./agent-backend";`（**无空格**）
  - 因空格不匹配，`.replace()` 未命中，`next/server` / `./agent-backend` 的 import 残留在被 `ts.transpileModule` 后通过 `data:` URL 动态 `import()` 的模块里；`data:` URL 无基准路径，无法解析裸模块名 `next/server`，导致加载失败。
- **路由判定**：**测试侧 Bug**（对源码格式化的脆弱环境假设），非前端源码 Bug —— 源码本身合法（`tsc`/`lint`/`build` 全通过，仅 import 括号间距的样式差异）。
- **修复**：仅修改测试文件 `tests/backend-proxy-range.test.mjs`，将三处精确字符串 `.replace()` 改为**空白不敏感的正则替换**：

  ```js
  .replace(/import\s+"server-only";/, "")
  .replace(/import\s*\{\s*NextResponse[^}]*\}\s*from\s*"next\/server";/, "const NextResponse = Response;")
  .replace(/import\s*\{\s*agentBackendUrl[^}]*\}\s*from\s*"[^"]*";/, 'const agentBackendUrl = (path: string) => "http://backend.test" + path;');
  ```
- **验证**：修复后 `node --test` 中原 2 个子测试（`文件分段请求保留范围与版本…`、`解压后的正文不沿用压缩前长度`）通过；整套件 7 个子测试全过（exit 0）。另以独立脚本实测确认替换后源码不再含 `next/server`、`/agent-backend` import，且 stub 正确注入。
- **可回滚性**：✅ 可回滚。改动仅限测试文件一行链（无源码改动）；回滚方式 = `git checkout tests/backend-proxy-range.test.mjs`（或删除该文件修改）。修复为最小、局部改动，不涉及任何依赖升级。
- **改动文件清单**：
  - `agenteam-web/tests/backend-proxy-range.test.mjs`（替换逻辑：精确字符串 → 空白不敏感正则）

### C. 修复方案（最小、可回滚，仅改测试文件）
1. **api-query**：在自研 react mock 中补 `useRef`，复用 `stateIndex` 计数器，保证跨渲染对应同一 ref 对象。
2. **conversation-model-menu**：`modules` 增加 `"@/lib/i18n/locale-provider": { useT: () => (key) => key }`。
3. **enterprise-gate**：`imports` 增加 `@/lib/i18n/locale-provider` 与 `@/lib/i18n/ui-message`；`LoadingTransition` 桩改为**深度渲染 children**（执行其内部的 `LoadEnterpriseIdentity`，从而真实驱动 loading/permission/error 状态机）；`useContext` 经 `LoadingTransition` 内 `Provider` 桩传递 identity。
4. **workflow-development**：`shared` 增加 `@/lib/i18n/locale-provider`（`useT` 恒等）与 `@/lib/i18n/translate`（`localizeCatalog` 原样返回）。

> 关键判断：`useT("中文")` 在组件里传入的是**中文字面量 key**，而真实 i18n 对未收录的中文 key 也是原样返回 —— 故 `useT` 用恒等函数 `(key) => key` 与真实行为**完全等价**，是最稳的桩。
