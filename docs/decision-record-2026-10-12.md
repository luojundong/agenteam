# 决策记录：AgenTeam 升级待拍板事项（推荐方案）

> 对应《升级思路分析》§4 的 7 项待拍板问题（Q1–Q7）。
> 本文给出**推荐默认决策 + 理由**，供负责人确认；标注「需确认」的为业务/战略层拍板项。
> 日期：2026-10-12。

## Q1 目标部署规模

- **推荐**：以「个人/小团队自部署」与「企业内部单实例」为第一阶段主战场；多租户 SaaS 作为第二阶段。
- **理由**：当前 `enterprise / workspace` 模型 + Docker Compose 多套变体已覆盖单实例；多租户改动面大、数据隔离风险高，宜后置。
- **影响**：决定 Q3 是否做多租户、运维投入与定价。
- 状态：⚠️ 需确认（产品 + 商业）。

## Q2 是否长期维护 Java 21 基线

- **推荐**：**长期维护 Java 21 基线**（不回退到 JDK17）。Spring Boot 4 明确要求较新 JDK；Java 21 为 LTS，生态成熟、风险低。
- **理由**：回退到 17 需替换 Spring Boot 4 专用启动器与部分 API，得不偿失；应为贡献者提供「一键装 JDK21」指引与 CI 矩阵。
- 状态：✅ 技术侧建议采纳（技术负责人确认）。

## Q3 是否做多租户

- **推荐**：第一阶段**按实例隔离**（每客户/每企业独立部署与数据库）；行级多租户后置。
- **理由**：行级隔离改动深、测试成本高、数据泄漏风险大；按实例隔离可立即支撑小企业客户，且 Redis Session 外置已具备无状态基础。
- 状态：⚠️ 需确认（架构 + 产品），建议在 Q1 确定后再定。

## Q4 模型厂商扩展范围

- **推荐**：优先补全**国产厂商**（DeepSeek / 通义 / 智谱）+ **本地模型**（Ollama / vLLM）；保持 OpenAI 兼容抽象与 MCP；向量检索栈（Embedding/Rerank + 向量库）作为第二阶段。
- **理由**：当前 `ModelProfile` + 自定义 base URL/密钥 已具扩展性；国产与本地模型是国内企业落地刚需；向量栈投入较大，先验证需求。
- 状态：⚠️ 需确认（产品），但技术侧可先行预置抽象。

## Q5 是否需要合规审计（等保/ISO/GDPR）

- **推荐**：第一阶段目标**国内企业**，走 **等保 / ISO 27001** 路径；GDPR/出海按需。
- **理由**：先聚焦可签单的国内市场；审计日志与发布期漏洞扫描（见 SECURITY.md）是准入前置。
- 状态：⚠️ 需确认（商务 + 法务）。

## Q6 编排引擎定位（自研增强 vs 深度依赖 AgentScope）

- **推荐**：**短期深度依赖 AgentScope 2.x**（已在其上构建 `ReActAgent`/`RuntimeContext`/`HarnessAgent`），但维持现有抽象层（`AgentModelFactory` / `WorkflowModelExecutionAdapter`）+ 回归测试，为长期解耦留口。
- **理由**：自研编排引擎投入巨大；当前抽象已降低耦合，跟随上游 2.x 小版本并季度回归即可。
- 状态：✅ 技术侧建议采纳（架构确认）。

## Q7 版本节奏（钉版 + 季度安全跟进 vs 紧跟上游）

- **推荐**：采用**「钉版 + 季度安全跟进」保守策略**。
- **理由**：Spring Boot 4 / Next 16 / React 19 / AgentScope 2 均为很新组合，紧跟上游易被静默击穿；钉版 + 季度评估补丁，配合 Renovate 与回归测试，风险可控。
- 状态：✅ 技术侧建议采纳（技术负责人确认）。
